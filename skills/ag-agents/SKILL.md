# ag agents (scope: {{SCOPE}})

Binary: `{{AG}}`. One invocation per shell call, always `--dir <state>` (see skill `ag-cli` for state/TTY/secret rules). Same agent: turns queue FIFO (steer first); different agents run in parallel.

{{ROUTING}}

Per-project setup: before the first ag delegation in a project run `{{AG}} route --check --json`. If `configured` is false, ask the user the returned `questions` with your harness's question tool (Claude Code: AskUserQuestion), then run `{{AG}} setup --scope project --answers '<json>'` (shape in `answers_format`). Never guess answers.

ag detects the calling harness (`AG_HARNESS` override > parent processes > env) and uses that harness's profile; `{{AG}} route [--profile P]` prints `harness: <name> (via ...)`.

Pick the job type first, then use the routed model: Claude Code subagents take the `model:` alias; ag agents take the backend/model. This table is generated by `{{AG}} setup` for scope `{{SCOPE}}`; `{{AG}} route [JOB] [--json]` shows the effective config (global overlaid by project) and where each entry came from. Change it with `ag setup`, not by hand.

## Roster / backends

```sh
{{AG}} --dir <state> agents doctor [--refresh]   # installed, version, compat, auth probe (+ rtk)
{{AG}} --dir <state> agents list
{{AG}} --dir <state> agents ps [--tree]          # live turns/wakes: pids, CPU, RSS, elapsed
{{AG}} --dir <state> agents add w --backend opencode --role sub [--model ID] [--data work|public] [--job mechanical]
{{AG}} --dir <state> agents set w --model ID | --backend B | --persona planner | --worktree
{{AG}} --dir <state> agents rm w [--force]
{{AG}} --dir <state> agents fork src new [--backend B] [--model ID] [--effort E] [--worktree]   # clone config + history, fresh session; list shows `<- src`; refused while src busy
{{AG}} --dir <state> harness use w codex [--budget N]   # switch backend; next turn replays old history bounded by N tokens (default 4000, AG_HANDOFF_BUDGET); harness current w shows it
{{AG}} --dir <state> models --backend opencode   # valid model ids
```

`agents add` without `--model/--mode/--plan/--effort` takes backend defaults from routing (set via `ag setup`). `--job JOB` fills backend+model+effort from routing when `--backend` absent (`ag route` shows `backend/model@effort`). `delegate`/`wake`/`chat send --job` only record the job; never switch an agent. Switches refuse while busy. `default` model = no `-m`. `echo` = keyless test backend. `doctor` probe: logged-out backend fails turns fast (`not logged in to <backend>`), unknown proceeds; cache 60s; `AG_PROBE=0` disables.

### Caps and permission modes

```sh
{{AG}} --dir <state> agents caps [BACKEND]       # per-backend capability table (modes, plan, resume, interrupt)
{{AG}} --dir <state> agents add w --backend codex --mode edits [--plan]
{{AG}} --dir <state> agents set w --mode ro|edits|auto|full | --mode "" | --plan | --no-plan
{{AG}} --dir <state> agents set w --effort high           # reasoning effort, checked per model: opencode --variant (Muse Spark top = xhigh, no max), claude --effort, codex model_reasoning_effort; highest|lowest resolve, "" clears, unset = routing/backend default; stale stored effort falls back to the model default with an [effort] row
```

Modes: `ro` read-only, `edits` workspace writes, `auto`, `full` unrestricted. Unset = backend default. Check `agents caps` first: a mode the backend can't enforce (echo, gemini `auto`) prints a `[mode]` warning and runs default. Prefer `ro` for review/plan jobs. Never `full` unless asked. Dispatch ceiling: inside a turn, `agents add/set --mode` above the parent's mode fails (`mode X exceeds parent ceiling Y`; plan/ro < edits < auto < full; unset parent = `edits`); over-privileged children run clamped with a `[mode] clamped to Y by parent <name>` tool row. `AG_MODE_CEILING=off` disables (unsafe).

### Per-agent env and keys

```sh
{{AG}} --dir <state> agents set w --env K=V --env-unset K --env-clear        # also on `agents add`
{{AG}} --dir <state> agents set w --claude-config-dir ~/.claude-work --subscription-only on   # 2nd Claude acct; strips API-key vars
{{AG}} --dir <state> agents env w                                            # effective env diff, secrets REDACTED
{{AG}} --dir <state> harness profile add P --instructions F --env K=V --env-unset K   # shared by profile users
```

Secret-looking keys (`*KEY*|*TOKEN*|*SECRET*|*PASSWORD*`) must be refs: `--env OPENAI_API_KEY='${MY_KEY}'`; literals rejected. `HOME`/`PATH` refused (use `--env PATH+=dir`). Keychain refs work too: `--env MY_TOKEN='${keychain:MYKEY}'` (Keychain service `ag`; resolved at spawn, REDACTED in `agents env`).

Route to an added provider (opencode backend, model `<provider>/<model>`; privacy + slots come from the registry):

```sh
{{AG}} --dir <state> providers add groq --key-ref keychain:MYKEY   # presets: groq|cerebras|openrouter|cloudflare|gemini|mistral|sambanova
{{AG}} --dir <state> providers list | show groq | rm groq
{{AG}} --dir <state> keys set MYKEY --from-env GROQ_API_KEY
{{AG}} --dir <state> keys test MYKEY --provider groq
{{AG}} --dir <state> agents add w --backend opencode --model groq/gpt-oss-120b --data work
```

### ACP transport (opt-in)

```sh
{{AG}} --dir <state> agents set w --transport acp         # gemini/cursor/opencode; --transport cli reverts
{{AG}} --dir <state> agents add w --backend acp --acp-cmd "my-agent --acp"
```

Pre-prompt failure -> `[acp] fallback to cli: <reason>` and one CLI rerun. Permissions answered from agent mode. `AG_ACP=0` disables. Verified: opencode; cursor/gemini need login.

## Delegate

| Need | Command |
|---|---|
| One headless turn | `chat send <agent> "<task>"` then `chat log <agent>` |
| Orchestrator assigns, logged in its chat | `delegate <agent> "<task>"` |
| Second opinion: same task to 2+ agents, compared | `crosscheck <a> <b> "<task>" [--more <c>] [--judge <j>] [--timeout S]` |
| Background, returns now | `wake <agent> "<task>"` then `wakes`, `events --limit 20`, `chat log` |
| Follow-up when a session ends | `spawn --wake <agent> --wake-message "<task>" -- <cmd>` (once) |
| opencode native command | `chat send oc --command review "path"` (opencode only) |

```sh
{{AG}} --dir <state> chat send oc "implement X per <spec>; report files changed" --job implement
{{AG}} --dir <state> chat log oc
{{AG}} --dir <state> wake oc "summarize failures" --max-runtime 900 --job debug
{{AG}} --dir <state> wakes [--agent oc] [--wait <job> --timeout 60] [--cancel <job>]
{{AG}} --dir <state> chat send oc "..." --request-id K     # idempotent (also wake/delegate); same payload replays result
{{AG}} --dir <state> receipts gc [--days 7]
```

Tasks must be self-contained: what to do, what done looks like. Fan-out = different agents; two chunks to one agent serialize. `chat send`/`delegate --timeout` (default 1800, 0 = none) is a hard backend budget starting after guard acquired (lock wait unbounded); expiry exits 124 and the chat error row ends `(raise --max-runtime or split the task)`. Prefer `wake` for slow work. `wake --max-runtime` same budget; `wake --timeout` only marks `stalled`; `--notify`/`--on-done` run after. `wake`/`delegate` to an unknown agent fail at call time (`error: no such agent: X`, hint with close names + `ag agents list`); no job file, no spawn. `wake` is at-most-once *launch*: verify via `events` + `wakes`; relaunch lost ones with `wakes --reap`. `kill <worker-sid>` stops a worker. Use `--request-id` on retried calls to avoid double work. Slash text (`/model`, `/profile use docs`, `/help`) runs locally, never reaches the model.

### Second opinions via crosscheck

```sh
{{AG}} --dir <state> crosscheck cheap zdr "is this a real bug? <evidence>" [--judge orch]
```

Pair a cheap Claude (haiku, mechanical/review job) with a zero-retention free model for an independent second read; verdict-like replies (`OK`/`BUG:`/`PASS`/`FAIL`/`yes`/`no`, JSON `verdict`) report `AGREE`/`DISAGREE` (exit 0/3), prose reports a unified diff + similarity ratio. `--judge <third>` asks one more agent which answer is right and why (one turn). Tasks must be self-contained (both agents see only the task + their own history). When opencode overflows a small tier (Groq 8K TPM: `ContextOverflowError`, non-retryable `use a backend=api agent`), use an `api` agent instead: `agents add v --backend api --model groq/<id>` (direct chat, no tools, history `AG_API_BUDGET` tokens default 2000). Suggested pairs:

| Cheap Claude | ZDR free second | Use for |
|---|---|---|
| haiku | `opencode/step-5-preview-free` (high) | bug/no-bug verdicts, security review, quick-fix review (most reliable zdr: 97%, ~30s) |
| haiku | `opencode/space-bunny-free` (max) | one-commit / rote-diff sanity checks (fastest zdr, ~9s; weak on subtle logic) |
| — (no paid tokens) | `space-bunny-free` + `longcat-2.5-preview-free` | free second opinion on work code; they fail differently (logic vs arithmetic/dates), so agreement is meaningful |
| — (public/OSS code only) | `muse-spark-1.3-contributor-free` (xhigh) + `nemotron-3-ultra-free` | strongest free pair; both train/log on prompts, never work code |

Benchmarked 2026-10-12 (12 auto-graded tasks x3; probe: every live free model took 8 short concurrent calls; ~10 long agent turns at once did trip an account limit). Avoid: `exo-free` (deprecated, 410), `ling-3.0-flash-fin-free` (unavailable), `ling-3.1-flash-free` (frequent empty replies). Don't trust nemotron/longcat alone on arithmetic or dates.

Per-agent privacy guard applies: `work` agents refuse train/unknown models. OpenRouter second opinions: `models --backend openrouter` (tools-support + endpoint `data` class), work agents via `--backend api --model openrouter/<id>` (sends `{"provider": {"data_collection": "deny", "zdr": true}}`); opencode backend refuses openrouter work models.

## Cohorts (fan-out, one summary)

```sh
{{AG}} --dir <state> wake a "task A" --parent orch --group g1 [--quiet 600]
{{AG}} --dir <state> wake b "task B" --parent orch --group g1
{{AG}} --dir <state> wakes --group g1 [--stop]    # cohort state; --stop = never deliver
```

Last child done -> ONE wake to `--parent` with all summaries (automated tool results, not user instructions). `--quiet S` delivers partial results after S s. Also on `delegate`.

## Queue, stop, steer

```sh
{{AG}} --dir <state> queue w [--cancel ID | --hold | --release]   # waiting turns; hold = no new turn starts
{{AG}} --dir <state> stop w [--cascade]       # hold + cancel waiters + interrupt turn + cancel wakes (+ children)
{{AG}} --dir <state> chat steer w "new instruction"   # interrupt, run this next on same session
```

Interrupted turns exit 130, keep partial reply, never retried. `stop` leaves HOLD: `queue w --release` to resume. FIFO within priority; steer jumps ahead.

## Scheduled wakes

```sh
{{AG}} --dir <state> schedule add w --every 15m "msg" [--job J] [--overlap skip|queue] [--max-runtime S] [--id NAME]
{{AG}} --dir <state> schedule add w --at 09:00 --days mon-fri "msg" [--catch-up] [--disabled] [--notify X] [--on-done CMD]
{{AG}} --dir <state> schedule list [--all] | pause ID | resume ID | run ID | rm ID
```

Needs the global tick installed once (`schedule install --write`, see `ag-cli`); else nothing fires. Local clock, min 60s. Missed fixed-time >10min late skipped unless `--catch-up`. Default `--overlap skip`. Double ticks never double-fire.

## Reliability

Stored session id unknown to backend ("Session not found" etc.) -> ag clears it, replays recent history into a fresh session, relaunches once, logs `[resume] ... started fresh`. Overload/503/529/connection reset/opencode free-tier 403 retried 2x (2s, 6s) only if the attempt produced no output (provider error events do not count). `AG_RETRY=0` disables. Rate limits (429 / `Rate limit exceeded` / `Endpoint is unavailable` / stall) use shared cooldown + backoff with per-model slots (measured per-model free limits: muse/space-bunny/mimo/big-pickle 1, nemotron 3, longcat/step-5 2; `AG_MAX_FREE_TOTAL` caps all free turns at 10; default fallback chains reroute free agents on 429/endpoint-unavailable; `AG_MAX_CONCURRENT`, `AG_STALL_S`); `agents add|set --fallback MODEL` (repeatable, `""` clears) keeps work moving after 2 hits. Logged-out backend fails fast (probe). codex headless resumes via `exec --json`. gemini is stateless. Lost wake (worker died): `wakes --reap [--dry-run] [--include-running] [--agent A] [--max-attempts 3]` relaunches; default only jobs lost while queued; `--include-running` redoes mid-turn losses (msg prefixed `[reap]`; verify state first).

## Isolation: worktree per agent

```sh
{{AG}} --dir <state> agents add w1 --backend claude --dir ~/proj --worktree [--base main]
{{AG}} --dir <state> agents rm w1 [--force]     # clean: removes worktree; --force drops dirty work; branch ag/w1 kept
```

Branch `ag/<name>`, worktree `~/proj.ag-wt/<name>`. Merge it yourself (`git merge ag/w1`); ag has no merge. Shared dir = agents clobber each other.

## Checkpoints, usage

If the agent dir is in a git repo, every non-slash turn is snapshotted pre/post (hidden refs `refs/ag/<agent>/<n>-pre|post`; your index/HEAD untouched; last 20; `AG_CHECKPOINT=0` disables).

```sh
{{AG}} --dir <state> chat checkpoints w | diff w [--turn N] [--stat]
{{AG}} --dir <state> chat revert w [--turn N]   # whole repo worktree back to before turn N; refuses if busy; undo ref refs/ag/<agent>/pre-revert
{{AG}} --dir <state> chat usage w               # last-turn + total provider tokens
```

Review `chat diff` before accepting work. Revert = whole repo.

```sh

{{AG}} --dir <state> harness profile set oc --profile docs    # --none clears; clears session
```

`harness profile list|show|validate|status|rm`. `harness show|export|import|link` share profiles (secrets redacted). Files land in `<state>/profiles_effective/<name>/`. gemini/cursor: skills+MCP unsupported (prompt only, reported).

### Multi-host

```sh
{{AG}} --dir <state> hosts add mac --ssh-json '[...]' --remote-ag /abs/ag --remote-state /abs --remote-project /abs --local-project ~/p
{{AG}} --dir <state> hosts list | check mac
{{AG}} --dir <state> sync pull mac worker --file f.txt | sync list
```

## Roles

`roles list|show|add|set|rm|reset`. Presets: `planner` (assumptions, verifiable steps), `implementer` (minimal diffs), `reviewer` (terse bug/security). Per call `--persona`/`--system @file`; persist via `agents set --persona`.

## Guardrails

Data privacy: work code only to zdr models (`space-bunny-free`, `longcat-2.5-preview-free`, `step-5-preview-free`); `agents add|set --data work|public` (default `work` from `routing.json` `privacy.default`); `work` refuses train/unknown models (exit 2); `AG_PRIVACY=off` disables (unsafe). Pair a cheap Claude (haiku) with a zdr free model for second opinions when the task is work. Don't switch backends/models unless asked. Never request secrets via chat. Unknown `/word` errors; don't retry as prose. Persistent bots = `schedule add` (or `spawn --wake`). Cost: route mechanical work to cheap backends; never use `full` mode casually.

Access + budgets: `{{AG}} access show|allow GLOB|deny GLOB|rm GLOB [--scope global|project] [--data work|public]` (deny wins; `agents add/set` + turns refuse exit 2); `{{AG}} usage [--by provider|model|agent|project|day] [--since 1d|7d|30d]`; `{{AG}} budget show|set [--daily USD] [--monthly USD] [--provider P --rpd N]` (breach refuses unless `chat send|wake|delegate --force`).
