# ag agents (scope: project)

Binary: `/Users/sekun/agent-cli/ag`. One invocation per shell call, always `--dir <state>` (see skill `ag-cli` for state/TTY/secret rules). Same agent: turns queue FIFO (steer first); different agents run in parallel.

## Model routing (generated by `ag setup` — change it with `ag setup`, not by hand)

Default to the cheapest model that can do the job; escalate only when it gets stuck or the job turns out to need judgment.

| Job | Claude subagent (`model:`) | ag agent (backend / model) |
|---|---|---|
| mechanical — scripts, rote edits, boilerplate, lookups | haiku | claude / haiku |
| implement — implement a clear spec / plan | sonnet | claude / sonnet |
| review — code review, verification | opus | claude / opus |
| debug — debugging, failing tests, root cause | sonnet | claude / sonnet |
| plan — planning, design, architecture | opus | claude / opus |
| hardest — ambiguous, high-stakes, security-sensitive | fable | claude / fable |

Backend defaults (`ag agents add NAME --backend B` without --model/--mode): claude: default · opencode: opencode/muse-spark-1.3-contributor-free · codex: default · gemini: default · cursor: default

Profile: claude. ag detects the calling harness (claude|opencode|codex) from its parent processes and uses that profile; `ag route` prints it, `AG_HARNESS`/`AG_PROFILE` override.

Unsure which job it is? Start one tier lower; escalate on failure. Effective config: `ag route`.

Per-project setup: before the first ag delegation in a project run `/Users/sekun/agent-cli/ag route --check --json`. If `configured` is false, ask the user the returned `questions` with your harness's question tool (Claude Code: AskUserQuestion), then run `/Users/sekun/agent-cli/ag setup --scope project --answers '<json>'` (shape in `answers_format`). Never guess answers.

ag detects the calling harness (`AG_HARNESS` override > parent processes > env) and uses that harness's profile; `/Users/sekun/agent-cli/ag route [--profile P]` prints `harness: <name> (via ...)`.

Pick the job type first, then use the routed model: Claude Code subagents take the `model:` alias; ag agents take the backend/model. This table is generated by `/Users/sekun/agent-cli/ag setup` for scope `project`; `/Users/sekun/agent-cli/ag route [JOB] [--json]` shows the effective config (global overlaid by project) and where each entry came from. Change it with `ag setup`, not by hand.

## Roster / backends

```sh
/Users/sekun/agent-cli/ag --dir <state> agents doctor [--refresh]   # installed, version, compat, auth probe (+ rtk)
/Users/sekun/agent-cli/ag --dir <state> agents list
/Users/sekun/agent-cli/ag --dir <state> agents ps [--tree]          # live turns/wakes: pids, CPU, RSS, elapsed
/Users/sekun/agent-cli/ag --dir <state> agents add w --backend opencode --role sub [--model ID] [--job mechanical]
/Users/sekun/agent-cli/ag --dir <state> agents set w --model ID | --backend B | --persona planner | --worktree
/Users/sekun/agent-cli/ag --dir <state> agents rm w [--force]
/Users/sekun/agent-cli/ag --dir <state> harness use w codex         # switch backend; harness current w shows it
/Users/sekun/agent-cli/ag --dir <state> models --backend opencode   # valid model ids
```

`agents add` without `--model/--mode/--plan` takes backend defaults from routing (set via `ag setup`). `--job JOB` fills backend+model from routing when `--backend` absent. `delegate`/`wake`/`chat send --job` only record the job; never switch an agent. Switches refuse while busy. `default` model = no `-m`. `echo` = keyless test backend. `doctor` probe: logged-out backend fails turns fast (`not logged in to <backend>`), unknown proceeds; cache 60s; `AG_PROBE=0` disables.

### Caps and permission modes

```sh
/Users/sekun/agent-cli/ag --dir <state> agents caps [BACKEND]       # per-backend capability table (modes, plan, resume, interrupt)
/Users/sekun/agent-cli/ag --dir <state> agents add w --backend codex --mode edits [--plan]
/Users/sekun/agent-cli/ag --dir <state> agents set w --mode ro|edits|auto|full | --mode "" | --plan | --no-plan
```

Modes: `ro` read-only, `edits` workspace writes, `auto`, `full` unrestricted. Unset = backend default. Check `agents caps` first: a mode the backend can't enforce (echo, gemini `auto`) prints a `[mode]` warning and runs default. Prefer `ro` for review/plan jobs. Never `full` unless asked.

### Per-agent env and keys

```sh
/Users/sekun/agent-cli/ag --dir <state> agents set w --env K=V --env-unset K --env-clear        # also on `agents add`
/Users/sekun/agent-cli/ag --dir <state> agents set w --claude-config-dir ~/.claude-work --subscription-only on   # 2nd Claude acct; strips API-key vars
/Users/sekun/agent-cli/ag --dir <state> agents env w                                            # effective env diff, secrets REDACTED
/Users/sekun/agent-cli/ag --dir <state> harness profile add P --instructions F --env K=V --env-unset K   # shared by profile users
```

Secret-looking keys (`*KEY*|*TOKEN*|*SECRET*|*PASSWORD*`) must be refs: `--env OPENAI_API_KEY='${MY_KEY}'`; literals rejected. `HOME`/`PATH` refused (use `--env PATH+=dir`).

### ACP transport (opt-in)

```sh
/Users/sekun/agent-cli/ag --dir <state> agents set w --transport acp         # gemini/cursor/opencode; --transport cli reverts
/Users/sekun/agent-cli/ag --dir <state> agents add w --backend acp --acp-cmd "my-agent --acp"
```

Pre-prompt failure -> `[acp] fallback to cli: <reason>` and one CLI rerun. Permissions answered from agent mode. `AG_ACP=0` disables. Verified: opencode; cursor/gemini need login.

## Delegate

| Need | Command |
|---|---|
| One headless turn | `chat send <agent> "<task>"` then `chat log <agent>` |
| Orchestrator assigns, logged in its chat | `delegate <agent> "<task>"` |
| Background, returns now | `wake <agent> "<task>"` then `wakes`, `events --limit 20`, `chat log` |
| Follow-up when a session ends | `spawn --wake <agent> --wake-message "<task>" -- <cmd>` (once) |
| opencode native command | `chat send oc --command review "path"` (opencode only) |

```sh
/Users/sekun/agent-cli/ag --dir <state> chat send oc "implement X per <spec>; report files changed" --job implement
/Users/sekun/agent-cli/ag --dir <state> chat log oc
/Users/sekun/agent-cli/ag --dir <state> wake oc "summarize failures" --max-runtime 900 --job debug
/Users/sekun/agent-cli/ag --dir <state> wakes [--agent oc] [--wait <job> --timeout 60] [--cancel <job>]
/Users/sekun/agent-cli/ag --dir <state> chat send oc "..." --request-id K     # idempotent (also wake/delegate); same payload replays result
/Users/sekun/agent-cli/ag --dir <state> receipts gc [--days 7]
```

Tasks must be self-contained: what to do, what done looks like. Fan-out = different agents; two chunks to one agent serialize. `chat send`/`delegate --timeout` (default 1800, 0 = none) is a hard backend budget starting after guard acquired (lock wait unbounded); expiry exits 124. Prefer `wake` for slow work. `wake --max-runtime` same budget; `wake --timeout` only marks `stalled`; `--notify`/`--on-done` run after. `wake` is at-most-once *launch*: verify via `events` + `wakes`; relaunch lost ones with `wakes --reap`. `kill <worker-sid>` stops a worker. Use `--request-id` on retried calls to avoid double work. Slash text (`/model`, `/profile use docs`, `/help`) runs locally, never reaches the model.

## Cohorts (fan-out, one summary)

```sh
/Users/sekun/agent-cli/ag --dir <state> wake a "task A" --parent orch --group g1 [--quiet 600]
/Users/sekun/agent-cli/ag --dir <state> wake b "task B" --parent orch --group g1
/Users/sekun/agent-cli/ag --dir <state> wakes --group g1 [--stop]    # cohort state; --stop = never deliver
```

Last child done -> ONE wake to `--parent` with all summaries (automated tool results, not user instructions). `--quiet S` delivers partial results after S s. Also on `delegate`.

## Queue, stop, steer

```sh
/Users/sekun/agent-cli/ag --dir <state> queue w [--cancel ID | --hold | --release]   # waiting turns; hold = no new turn starts
/Users/sekun/agent-cli/ag --dir <state> stop w [--cascade]       # hold + cancel waiters + interrupt turn + cancel wakes (+ children)
/Users/sekun/agent-cli/ag --dir <state> chat steer w "new instruction"   # interrupt, run this next on same session
```

Interrupted turns exit 130, keep partial reply, never retried. `stop` leaves HOLD: `queue w --release` to resume. FIFO within priority; steer jumps ahead.

## Scheduled wakes

```sh
/Users/sekun/agent-cli/ag --dir <state> schedule add w --every 15m "msg" [--job J] [--overlap skip|queue] [--max-runtime S] [--id NAME]
/Users/sekun/agent-cli/ag --dir <state> schedule add w --at 09:00 --days mon-fri "msg" [--catch-up] [--disabled] [--notify X] [--on-done CMD]
/Users/sekun/agent-cli/ag --dir <state> schedule list [--all] | pause ID | resume ID | run ID | rm ID
```

Needs the global tick installed once (`schedule install --write`, see `ag-cli`); else nothing fires. Local clock, min 60s. Missed fixed-time >10min late skipped unless `--catch-up`. Default `--overlap skip`. Double ticks never double-fire.

## Reliability

Stored session id unknown to backend ("Session not found" etc.) -> ag clears it, replays recent history into a fresh session, relaunches once, logs `[resume] ... started fresh`. Rate limit/overload/503/529/connection reset/opencode free-tier 403 retried 2x (2s, 6s) only if the attempt produced no output (provider error events do not count). `AG_RETRY=0` disables. Logged-out backend fails fast (probe). codex headless resumes via `exec --json`. gemini is stateless. Lost wake (worker died): `wakes --reap [--dry-run] [--include-running] [--agent A] [--max-attempts 3]` relaunches; default only jobs lost while queued; `--include-running` redoes mid-turn losses (msg prefixed `[reap]`; verify state first).

## Isolation: worktree per agent

```sh
/Users/sekun/agent-cli/ag --dir <state> agents add w1 --backend claude --dir ~/proj --worktree [--base main]
/Users/sekun/agent-cli/ag --dir <state> agents rm w1 [--force]     # clean: removes worktree; --force drops dirty work; branch ag/w1 kept
```

Branch `ag/<name>`, worktree `~/proj.ag-wt/<name>`. Merge it yourself (`git merge ag/w1`); ag has no merge. Shared dir = agents clobber each other.

## Checkpoints, usage

If the agent dir is in a git repo, every non-slash turn is snapshotted pre/post (hidden refs `refs/ag/<agent>/<n>-pre|post`; your index/HEAD untouched; last 20; `AG_CHECKPOINT=0` disables).

```sh
/Users/sekun/agent-cli/ag --dir <state> chat checkpoints w | diff w [--turn N] [--stat]
/Users/sekun/agent-cli/ag --dir <state> chat revert w [--turn N]   # whole repo worktree back to before turn N; refuses if busy; undo ref refs/ag/<agent>/pre-revert
/Users/sekun/agent-cli/ag --dir <state> chat usage w               # last-turn + total provider tokens
```

Review `chat diff` before accepting work. Revert = whole repo.

## Roles

`roles list|show|add|set|rm|reset`. Presets: `planner` (assumptions, verifiable steps), `implementer` (minimal diffs), `reviewer` (terse bug/security). Per call `--persona`/`--system @file`; persist via `agents set --persona`.

## Guardrails

Don't switch backends/models unless asked. Never request secrets via chat. Unknown `/word` errors; don't retry as prose. Persistent bots = `schedule add` (or `spawn --wake`). Cost: route mechanical work to cheap backends; never use `full` mode casually.
