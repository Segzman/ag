# Spec: `--escalate` ladder + `--allow-cmd` for claude (2026-10-30)

Why: ag's pitch is "start on the cheapest model, escalate on failure, with receipts". `--verify` already
checks the work; nothing acts on a failed check. And claude agents in `edits` mode cannot run tests, so a
cheap model can't self-check.

## F1. `--allow-cmd` for the claude backend

- `agents add|set NAME --allow-cmd PATTERN` (existing flag, today opencode-only) also applies to claude.
- For a claude agent whose mode is `edits`, each pattern P adds `--allowedTools "Bash(P*)"` to the claude argv
  (one `--allowedTools` flag followed by all `Bash(...)` entries), placed before the prompt.
- Other modes: no `--allowedTools` (ro stays read-only; auto/full don't need it).
- `backend_argv(...)` gains a keyword `allow_cmd=()`; run_turn passes the agent's `allow_cmd` list.
- Help text for `--allow-cmd` mentions claude too.

## F2. `--escalate MODEL[,MODEL...]` on `chat send`

- Only valid with `--verify`; otherwise error `--escalate needs --verify` (non-zero rc, nothing runs).
- Run the turn as today (agent's own model). If verify exit != 0, run another turn on the SAME agent/session
  with the next model as a one-turn override (roster unchanged), message:
  `<original task>\n\nThe previous attempt failed verification (\`<cmd>\`, exit N). Output:\n<tail>\nFix it.`
  Then verify again. Stop at the first verify exit 0 or when the list is exhausted.
- Per-turn model override: `run_turn(..., model=None)` keyword; when set it replaces `a["model"]` for that turn
  only (privacy/access/budget checks use the override). Never written to agents.json.
- Result (`chat send --json` data): existing keys keep describing the LAST attempt (`reply`, `exit`, `verify`),
  plus `escalation`: list of `{"model": <model used>, "exit": <backend exit>, "verify_exit": <int>}` — one entry
  per attempt, first entry = the agent's own model. Only present when `--escalate` given.
- Chat log: one `[escalate] -> MODEL (verify exit N)` tool row before each escalated attempt.
- Backend failure (exit != 0, error) on an attempt also escalates (treat as failed).
- Docs: README (verify section) + skills/ templates (ag-agents) per repo rule; `tests/test_ag_doc_coverage.py` must pass.

Out of scope: `wake`/`delegate` escalation (later), reverting the failed attempt's edits (checkpoints already allow it).
